# 退款与售后 Skill

## 目标

基于平台政策和知识库内容，帮助用户判断退款或售后是否可办理，并说明材料和下一步流程。

## 触发条件

当用户提到以下内容时，应使用本技能：

- 退款、退货、换货
- 售后、质量问题、破损
- 赔付、补偿、投诉
- 不想要了、买错了、收到货不满意

## 必要信息

- 订单号
- 商品状态
- 签收时间
- 售后原因
- 必要时收集图片、联系方式或补充说明

## 执行步骤

1. 判断用户问题属于退款、退货、换货还是投诉赔付。
2. 优先调用 `lookup_policy` 查询固定政策。
3. 如果政策信息不足，调用 `search_knowledge_base` 检索更详细规则。
4. 根据政策判断是否满足条件，并明确说明原因。
5. 如果需要人工审核、材料补充或用户情绪强烈，说明转人工的原因。
6. 多 Agent 模式先等待订单等依赖任务完成。只有 action 任务且调用方已确认，才使用
   当前工具列表中的 `create_support_ticket` 或 `submit_after_sales_request`。
7. 当前售后申请为模拟受理，不发生真实资金流转；确认参数不是付款授权。

## 回复要求

- 不要承诺一定退款、一定赔付或一定通过审核。
- 说明政策依据和用户需要准备的材料。
- 信息不足时先追问关键字段。
- 对用户情绪先表达理解，再给出可执行步骤。

## 转人工条件

- 超出标准退款政策。
- 涉及大额赔付或投诉升级。
- 用户提供的信息和政策冲突。
- 用户明确要求人工客服跟进。
